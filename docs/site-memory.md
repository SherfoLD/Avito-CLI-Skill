# Avito — site memory

Consensus knowledge only: what anyone building a read-only client against Avito
runs into, regardless of how they build it. Findings specific to our commands
stay in their domain file under [areas/](areas/).

## Domains

| Purpose | Host |
|---|---|
| Everything the commands read | `www.avito.ru` |
| Photo CDN | `*.img.avito.st` |

A single origin, no separate API host. Regional slugs (`/moskva/...`,
`/tver/...`) are part of the canonical route and are generated by Avito, never
assembled by hand.

## Access

- Read the SSR bootstrap of the document, then call the internal JSON endpoints
  from the same origin. Everything happens inside a browser the user owns.
- No login, no cookie handling, no token. Everything read here is visible to an
  anonymous visitor.
- Prime the origin with a lightweight navigation to
  `https://www.avito.ru/robots.txt` before same-origin fetches; never navigate to
  the catalog page, which pulls scripts, images and telemetry.
- An anonymous direct GET from Node answers `HTTP 429` with `server: QRATOR` and
  a CAPTCHA. The browser context is the only path.

## Known endpoints

The SSR document is the primary carrier:
`script[type="mime/invalid"][data-mfe-state="true"]` → `loaderData`. After
hydration the landed page keeps neither that script nor `searchCore`, so the
schema must be read by one same-origin document fetch and never from the
rendered DOM.

- `GET /?q=<query>` — a redirect payload naming the canonical route; the visible
  search form is not used
- `GET /<canonical-search-route>` — the SSR document;
  `loaderData.data.catalog.items`, `searchCore`, `filtersV2`,
  `rubricators.side.nodes`. `seoNavigation.breadcrumbs.links` also arrives but has
  been read by no command since 2026-08-15 (D-034)
- `GET /web/1/js/items` — catalog refinement; requires the fresh `searchCore`
  context, `spaFlow=true`, `useReload=true` and the opaque context copied
  unchanged. Historically the endpoint that returns `429`
- `GET /items/ads<full-item-pathname>` — item details, `buyerItem`
- `GET /web/7/user/<ratingUserKey>/ratings` — the seller review feed; `offset`,
  `photoOnly`
- `GET /web/1/slocations?q=` — location suggestions
- `GET /web/1/search/locations?locationId=` — location capabilities, including
  the `smallRadius` kilometre list
- `GET /web/2/locations/{metro,districts}?locationId=` — geo directories
- `GET /web/1/coords/by_address?address=` — the geocoder

All are undocumented and internal-unstable: validate fail-closed, one request
per call, no retry.

## Fields

Visible card values do not live in the flat item object. Read them from the iva
steps:

| Value | Carrier | Flat field (fallback only) |
|---|---|---|
| Card text | `iva.DescriptionStep[].payload.description` | `item.description` — empty in the SSR catalog |
| Shown price | `iva.PriceStep[].payload.priceDetailed` | `item.priceDetailed` — the base price, differs whenever a bonus applies |
| Location line | `geo.geoReferences[0]` | `item.location.name` — was null on 39 of 50 rows |
| Reservation | `catalog.items[].isReserved` | none; the visible plaque is drawn from this boolean |

Photos: never name a size. Take the largest variant whose key parses as
`<width>x<height>` — a card ships six sizes, an item gallery two, and each
variant has its own opaque URL, so a larger one cannot be derived from a smaller
one.

## Pitfalls

1. **`robots.txt` contains the word `captcha`** in its `Clean-param` directives. A text challenge detector run over the primed origin fires on it. Read the challenge from the target response and from the rendered page instead.
2. **Avito validates nothing and reports nothing.** An unknown metro ID is silently ignored, a station from another city is silently accepted, `metro` and `district` are accepted together, an unknown review sort is silently downgraded to `date_desc`, and an unknown rating key returns `200` with an empty feed. Every guard has to live on your side.
3. **`searchCore.activeTab` is not proof** that a geo mode applied: `smallRadius` comes back even with no geo parameters at all. Assert on `searchCore.metroId` / `districtId` / `searchRadius` / `geoCoords` instead.
4. **The city cannot be applied by editing the URL.** `locationId` in the document route is silently ignored; the only working path is the items API.
5. **Any `?q=` query is canonicalised into a category route**; only whether `q` survives differs. On a dissolved result `searchCore.query` is empty too, so exact query matching cannot be a postcondition.
6. **The page size belongs to Avito** — 50 listings, 25 reviews — and no page-size parameter exists. The `limit=300` seen in older material belongs to the filter-option suggest endpoint, not the catalog. The review feed ignores `limit` outright.
7. **The geocoder rewrites the address silently**: a missing house number snaps to a neighbour, a multi-city address resolves to one of them without any ambiguity flag. Return `normalizedAddress` alongside the point.
8. **The seller has three identifiers.** `seller.hashId`, the `/user/<id>|/brands/<id>` route segment, and `buyerItem.rating.userKey` for the review feed are all different values.
9. **A private seller has no identity for an anonymous caller.** Without a session the catalog ships an empty `iva.UserInfoStep` on those cards (14 of 50 and 22 of 50 rows on two pages of one route) and the item API blanks every profile link while `seller.name` becomes the placeholder `Пользователь`. The flat `rating` survives on the same card, and companies (`/brands/...`) are unaffected — so seller ID and seller rating must be nullable independently of each other. The profile route itself still answers `200`; only the payload withholds it.
10. **There is no seller reviews page.** The visible link is the `#open-reviews-list` modal anchor; `/user/<hashId>/reviews` answers `404`.
11. **A refinement request replaces a filter, it never adds to it.** The items API is rebuilt from the current `searchCore.params`, so applying one value of a filter and then another drops the first: several values of one filter must travel in one request as `params[id][0]`, `params[id][1]`, …. Avito confirms the whole set in both `searchCore.params` and `filtersV2.currentValue`, and accepts several different filters in one request too.
12. **`429` and hCaptcha are real and recur.** Stop without interacting, do not retry, do not weaken validation.
13. **`filtersV2.currentValue` is authoritative for `params[...]` and unreliable for the short keys.** For `price`, `user`, `d`, `localPriority` and `sort` it arrives stale or omitted even when the response `searchCore` and the server-generated URL prove the value was applied. Read those five from `searchCore` (`priceMin`/`priceMax`, `owner`, `withDeliveryOnly`, `localPriority`, `sort`) and treat the schema as a vocabulary only. Both carriers ship in the same SSR bootstrap, so this costs no extra request.
14. **A refinement request is a full state snapshot, not an incremental operation.** Everything the call does not change — category, location, metro, districts, the point and radius, and every other `params[...]` — has to be copied into the request from the fresh `searchCore` and then asserted as preserved in the response, or it silently disappears from the result.
15. **One filter type ships in two option forms, and one range type pretends to be a list.** `values` of a `sectionedMultiselect` is either a flat option list or wrappers `{id, title, options}` naming a group of the visible control — bikes send the flat form, car brands and oil manufacturers send the grouped one, and the group `id` is empty in every case observed. Read through the wrapper and expect the same option in more than one group: «Марка» repeats all 20 popular brands inside «Все», so a uniqueness guard over the flattened list fires on a normal page. A `slider` is not an enum despite carrying `values` with option IDs: it is the range Avito draws as a track, with the same `inputs.from` / `inputs.to` block as `numericRange`.
16. **A `params[...]` value has three shapes, and only one of them is a list.** A range — `numericRange` or `slider` — is sent as the two keys its own `inputs` block declares, `params[<attrId>][from]` and `[to]`, and comes back as `{from, to}` in both `searchCore.params` and `filtersV2.currentValue`. The bound nobody set is `0` in `searchCore` and `null` or `""` in the schema. A checkbox (`bannerCheckBoxWithImage`, `boolean`) has no vocabulary at all and is sent as the bare key with `1`. Two traps follow: a range in `searchCore.params` is an object, so any carry-over that treats `params[...]` as a list of values dies on the first URL that has one, and any comparison that flattens it makes every range look equal to every other one.
17. **A `checkboxGroup` with `values: []` is a heading, not a filter.** Its options are its `content` — separate filters with their own IDs — and its own ID is synthetic and unstable: the same route answered `params[156269380000]` and `params[156272960000]` for the same group within one session. It has no control of its own in the visible form, which is why applying it is accepted and does nothing. Return its children and drop the wrapper, exactly as with a section inside `values`.
18. **`keywords` is an ordinary list of values that happens to be typed by hand.** «Слова в описании» (`params[149569]`) and «Скрыть объявления со словами» (`params[164865]`) travel as `params[<attrId>][0]`, `[1]`, … and come back as a list of strings in both carriers. Avito preserves case, spaces and punctuation exactly — `Kingston HyperX` and `б/у` return character for character — so an exact-match postcondition is safe. Their `defaultTitle` can contain a literal `\n` sequence.
19. **Not every control in the filter form holds a value.** `garageEntrypoint` («Укажите авто») is a card that opens Avito's car picker: no `values`, no `inputs`, and its `displaying.carInfmParams` names the three ordinary filters it fills — brand `110000`, model `110001`, generation `110005`, each of which appears in the schema as the previous one is applied. Sending its own key is not even echoed back, unlike the heading in 17 above: `searchCore.params` and `filtersV2.currentValue` both stay empty and Avito drops the key from the canonical URL. It belongs in a type map as something that never yields a syntax, not as an enum with an empty vocabulary.
20. **A single vocabulary can run to five digits.** «Производитель» (`params[110548]`) on truck parts ships 12150 options in one `multiselect`, all unique and well formed, against exactly 1000 for the same key one branch away under car parts. Any plausibility ceiling below that refuses real pages, and truncating the list silently is worse — size the guard to catch broken data, not big data.
21. **Avito echoes a `params[...]` key it does not apply.** `params[156269380000]=1` (a `checkboxGroup` shipped with no `values`) comes back inside `searchCore.params` with the result count unchanged and `filtersV2.currentValue` still empty. `searchCore` alone therefore proves nothing about `params[...]`; the schema is what separates an applied value from an echoed one.

## Reference shapes

| Shape | Command |
|---|---|
| SSR catalog read + guarded API refinement | `search` |
| Stateless pagination over an immutable URL | `get-page` |
| Many validated filters in one request through the items API | `apply-filters` |
| Full SSR schema reader with authoritative current values | `get-filters` |
| Navigation resolved from rendered state, then followed | `move-category` |
| API-first detail with hydration and DOM fallbacks | `get-item` |
| A feed keyed off another response | `get-seller-reviews` |
| Name and directory resolvers | `get-location`, `get-coords` |
